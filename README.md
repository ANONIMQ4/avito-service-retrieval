# Кандидатогенерация для объявлений услуг


## Данные и признаки

- `search_query` и `search_infm_params_text` описывают искомую услугу и уточняющие фильтры. Они входят в текст запроса для обоих способов поиска.
- `item_title_raw`, `item_infm_params_text` и `item_description_raw` описывают услугу исполнителя: заголовок даёт короткое название, параметры и описание добавляют детали.
- `search_location_id`, `item_location_id`, `item_latitude` и `item_longitude` используются для географического отбора.
- Положительные пары из `train.parquet` используются для оценки связей между поисковыми локациями и локациями выбранных объявлений.

`search_category` и `search_is_delivery_search` участвуют в определении уникального запроса при разбиении данных. Отдельные правила фильтрации по этим полям в итоговом поиске не применяются. Цена и числовые показатели рейтинга не используются.

## Метод

Объявления отбираются двумя независимыми способами:

1. BM25 по заголовку, параметрам и началу описания. Заголовок повторяется дважды, чтобы увеличить вклад его слов. Параметры BM25: `k1=1.2`, `b=0`, минимальная частота слова по документам — 3. Запрос состоит из поискового текста и текстовых фильтров.
2. Косинусная близость эмбеддингов открытой модели `intfloat/multilingual-e5-small`. Для запроса используется префикс `query:`, для объявления — `passage:`; среднее по токенам с маской, L2-нормировка, максимум 128 токенов.

Поиск ведётся в пределах точной локации и связанных локаций, выявленных только по обучающим парам. Для запроса, у которого нет объявлений в точной локации, базовый охват формируется по первым пяти связанным локациям. Дополнительно ищутся объявления в радиусе 100 км от центра локации. Центр — медиана координат объявлений данной локации либо медиана координат выбранных в обучении объявлений, если в каталоге такой локации нет. Для запросов без точной локации радиусной ветке отводится 20 из 100 кандидатов, с точной — 10 из 100. Точные объявления в радиусной ветке сохраняются независимо от погрешности координат центра.

До радиусного расширения основной список смешивается со списком из первых десяти связанных локаций с бюджетом 90/10. Квоты при смешивании приблизительные: на них влияют повторы и возможный недостаток кандидатов. Координаты задают оценку центра локации, а не точный адрес пользователя.

Для каждого из двух текстовых способов остаётся до 100 кандидатов. Итоговые 50 уникальных объявлений выбираются методом Reciprocal Rank Fusion с константой 5. 

Для построения географических связей исходный `train.parquet` детерминированно делится по уникальным запросам: 70% для обучения, 30% для локальной проверки. 

## Проверка качества

Группировка при разбиении выполняется по полному набору `search_*`: все пары одного такого запроса попадают в одну часть. Локальная тестовая часть содержит 106 371 запрос.

Метрика — средний Recall@50 по запросам. Географические связи строятся только по обучающей части. Радиус и квоты дополнительно подбирались на отложенной части train с разделением по текстам запросов.

## Анализ ошибок

1. **Точная локация слишком сильно ограничивает поиск.** Подходящее объявление может находиться поблизости. Поэтому радиусный поиск добавлен и для запросов с точной локацией.
2. **Широкая география добавляет нерелевантные объявления.** Радиус не заменяет основной список целиком: его влияние ограничено квотами, подобранными на отложенных данных.

## Файлы решения

- `train.py` — обучение географических связей и подготовка эмбеддингов.
- `inference.py` — поиск кандидатов и формирование ответа.
- `cache/geo_artifact.json` — связи локаций и резервные координаты центров.
- `cache/item_embeddings.npy`, `cache/query_embeddings.npy` — готовые эмбеддинги.
- `cache/item_embeddings.json`, `cache/query_embeddings.json` — прогресс расчёта эмбеддингов для продолжения после прерывания.
- `requirements.txt` — версии зависимостей.
- `answer.csv` — отправленный результат.

## Воспроизведение

Для запуска с готовым кэшем достаточно двух файлов бенчмарка; `train.parquet` нужен только для повторного обучения географических связей. Исходные данные и веса E5 в репозиторий не включены.

Кэш хранится в Git LFS. После установки Git LFS выполните:

```bash
git lfs install
git clone https://github.com/ANONIMQ4/avito-service-retrieval.git
cd avito-service-retrieval
git lfs pull
python3.10 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
mkdir -p data
```

Положите исходные `benchmark_queries.parquet` и `benchmark_items.parquet` в `data/`, сохранив порядок строк. Затем запустите:

```bash
python inference.py
```

`train.py` строит компактный `cache/geo_artifact.json` из размеченного `train.parquet` и готовит кэш эмбеддингов по неразмеченным файлам бенчмарка. Артефакт и кэш уже включены. `inference.py` читает их, строит BM25-индекс по корпусу и записывает `answer.csv`. Если кэш эмбеддингов отсутствует, `inference.py` вызывает функцию его подготовки из `train.py`. Для повторного получения уже готового ответа достаточно запустить только `inference.py`.

С полным кэшем веса модели не нужны: инференс читает готовые эмбеддинги и не обращается к внешним API. Скрипт проверяет сигнатуры текстов, чтобы случайно не использовать кэш с другой версией данных. Если кэш удалён или неполон, для его пересчёта используется модель `intfloat/multilingual-e5-small`: при отсутствии локальных весов они автоматически скачиваются с Hugging Face. Для первого скачивания нужен интернет; сами эмбеддинги рассчитываются локально. Результат сохраняется в `answer.csv` рядом со скриптами.

### Проверка воспроизводимости

Использовались Python 3.10, Linux и NVIDIA GPU с PyTorch 2.5.1 / CUDA 11.8. Скрипт автоматически выбирает CUDA, MPS или CPU и выводит устройство в лог. 
Для точного воспроизведения используйте зафиксированные зависимости и готовый кэш. При смене библиотек или устройства порядок кандидатов с равными или очень близкими оценками может отличаться. В частности, при повторном обучении порядок связанных локаций с одинаковой частотой зависит от версии библиотек. Запуск перезаписывает `answer.csv`.

Весь код решения — в двух файлах, `train.py` и `inference.py`. Классические библиотеки: NumPy, pandas, SciPy, scikit-learn; нейросетевая часть: PyTorch и Transformers. Модель E5 открытая, без дообучения в этом решении.
